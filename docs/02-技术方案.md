## 1. 技术栈与版本

| 项 | 决定 | 说明 |
|---|---|---|
| 桌面框架 | Electron **45.4.1**（锁精确版本） | 阶段 1 验证后不中途升级；如遇阻塞退回 Electron 44 最新补丁版 |
| 渲染层 | 原生 HTML / CSS / JavaScript | 普通 `<script>` + IIFE，不使用 React/Vue/TS/打包器 |
| 主进程 | CommonJS | 与 Electron 加载方式一致，避免 ESM 复杂度 |
| 打包 | electron-builder **26.18.0**，`--dir` 目录版 | 生成绿色文件夹，无安装器 |
| 测试 | Node 内置 `node:test` | 不引入 Jest/Playwright |
| 运行时依赖 | **零第三方依赖** | 只用 Electron + Node 内置模块 + 浏览器 API |

选型依据：本机无 dotnet/python/rust 与 VS 编译环境；Node 26 与网络可用；Electron 44+ 剪贴板 API 已改为异步（官方 breaking changes 确认）。刻意避开原生模块（如 better-sqlite3），规避 ABI 编译风险。

## 2. 进程架构

**主进程是唯一数据源**，负责：剪贴板轮询、数据存取、清理、搜索、托盘、设置、窗口生命周期。
preload 通过 `contextBridge` 只暴露白名单 IPC 方法。
渲染层只做展示与交互，不直接接触文件系统与剪贴板。

```
[剪贴板] ←轮询→ main (watcher + store + items + settings)
                     ↕ IPC（白名单、参数校验）
                  preload (contextBridge)
                     ↕
                renderer (HTML/CSS/JS)
```

### 2.1 模块划分（src/main）

| 文件 | 职责 |
|---|---|

| `clipboard-watcher.js` | 轮询、基线管理、自写抑制、内容提取（唯一剪贴板访问点） |
| `store.js` | 索引加载/原子写入/`.bak`/损坏恢复/防抖/flush |
| `items.js` | 业务逻辑：ingest、去重、置顶、删除、清空、过期清理、上限裁剪、搜索、分页 DTO |
| `settings.js` | 设置读取/校验/写入 |
| `tray.js` | 托盘图标与菜单 |
| `ipc.js` | IPC 注册、参数校验、错误包装 |
| `protocol.js` | `clipimg://` 缩略图协议（严格路径校验） |
| `logger.js` | 滚动日志、限频（不记录剪贴板正文） |
| `src/preload.js` | 白名单桥接 |
| `src/renderer/*` | 页面结构与交互（无 Node 权限） |

### 2.2 IPC 白名单（命名 `域:动作`）

| 通道 | 参数 | 返回 | 说明 |
|---|---|---|---|
| `items:query` | `{ search?, offset, limit }` | `{ total, items: DTO[] }` | offset/limit 校验上限（limit ≤ 200） |
| `items:copy` | `{ id }` | `{ ok }` | 主进程写回剪贴板并自写抑制 |
| `items:pin` | `{ id, pinned }` | `{ ok }` | |
| `items:remove` | `{ id }` | `{ removed, cancelled? }` | 置顶项由主进程弹原生确认框 |
| `items:clear` | 无 | `{ cleared, cancelled }` | 主进程确认框显示条数，保留置顶 |
| `settings:get` | 无 | settings DTO | |
| `settings:update` | `{ retentionDays?, launchAtLogin? }` | `{ ok, cancelled?, error? }` | 主进程校验并处理缩短天数确认 |
| `app:open-data-folder` | 无 | `{ ok }` | shell.openPath(dataDir) |
| `app:get-info` | 无 | `{ version }` | 设置页显示版本 |
| `win:hide` | 无 | 无 | 关闭按钮/ Esc |
| 事件 `items:changed` | main → renderer | 无 | 数据变化通知刷新 |
| 事件 `app:error` | main → renderer | `{ message }` | 顶部错误条（中文、不含技术细节） |

DTO 只含展示所需字段：`id, type, previewText(≤500 字符), thumbUrl?, width?, height?, createdAt, pinned, pinnedAt`。渲染层拿不到全文与原始图片。

## 3. 剪贴板采集（核心）

### 3.1 Electron 45 API 事实（2026-11-19 官方文档核实）

- 来自 Electron 44.0 的 breaking change：`clipboard` 模块重构为 W3C Clipboard API 风格。
- `clipboard.readText()` → `Promise<string>`；`clipboard.writeText(text)` → `Promise<void>`。
- `clipboard.read()` → `Promise<ClipboardItem[]>`；`item.types: string[]`；`await item.getType(mime)` → `Blob`（惰性）。
- `clipboard.write([new ClipboardItem({ [mime]: Blob | string })])` → `Promise<void>`。
- `clipboard.has(mime)` → `Promise<boolean>`；`clipboard.clear()`。
- 旧的 `availableFormats / readImage / writeImage / readHTML / readRTF...` 已移除。
- 渲染进程不再暴露 `clipboard` 模块（45.0 移除）。
- `text/uri-list` 对应 Windows 的 CF_HDROP（复制文件）。

### 3.2 轮询算法（非重入）

```
每 600ms 一个 tick（上一次未结束则跳过本次）:
  if paused or busy: return
  busy = true
  try:
    text = await clipboard.readText()
    items = await clipboard.read()           // 取 types；必要时才 getType
    types = items.flatMap(i => i.types)
    if types 含 'text/uri-list': 跳过（文件复制，不记录）
    if text.trim() 非空:
        if text !== lastSeenText:
            hash = sha256(text, utf8); ingestText(text, hash)
        lastSeenText = text
    else if types 含 image/*:
        if 距上次图片读取 ≥ 1500ms:
            blob = await imageItem.getType(imageMime)
            buf = Buffer.from(await blob.arrayBuffer())
            if buf.length ≤ 20MB:
                png = 统一转 PNG（必要时 nativeImage 转换）
                h = sha256(png)
                if h !== lastSeenImageHash: ingestImage(png, h)
                lastSeenImageHash = h
  catch(e):
    限频记录日志（类型/时间，不含正文），下一 tick 重试
  finally:
    busy = false
```

补充规则：

- **文本优先**：同一次复制同时含文字与图片时（如网页富文本），只记录文字；文字为空才记录图片。MIME 细节以阶段 1 实测（Chrome、Word、微信、截图工具）为准。
- **空白文字**跳过；文字原样保存（不裁剪），哈希按 UTF-8 原始字节。
- **文件复制**：types 含 `text/uri-list` 的整次复制跳过。
- **自写抑制**：点击卡片复制时，先设置抑制标记并同步更新 `lastSeenText` / `lastSeenImageHash` 基线；写入期间及之后短暂窗口内不采集，保证「点击复制不改变排序、不刷新时间」。
- **启动基线**：启动后首次成功读取剪贴板只更新基线，不写入历史。
- **图片转换**：如剪贴板提供 `image/png` 直接用；否则用 `nativeImage.createFromBuffer` 转 PNG 后保存。缩略图统一为 PNG（最长边 ≤400px），存入 `thumbs/`，避免依赖 webp 编码器。
- **日志**：只记录事件类型、耗时、字节数、哈希前 8 位；**绝不记录正文或图片内容**。

### 3.3 性能预算与阈值

| 指标 | 目标 | 说明 |
|---|---|---|
| 文本检测延迟 | ≤ 1s | 600ms 轮询 + 处理 |
| 图片检测延迟 | ≤ 2s | 1.5s 图片读取间隔 |
| 空闲 CPU（纯文本） | < 1% 单核 | 阶段 1/5 任务管理器实测 |
| 持续 4K 图片 CPU | < 3% 单核 | 超标则图片间隔调至 2–3s 或相同指纹退避 |
| 内存 | 2 小时无持续增长 | 阶段 5 实测 |

### 3.4 已知限制（同步写入需求文档与使用说明）

- 轮询漏记窗口（文字 600ms / 图片 1500ms）。
- 剪贴板内容未变化时的重复复制无法感知。
- 部分软件（密码框、安全软件）阻止记录。

## 4. 数据与存储

### 4.1 数据目录

- 打包版：`<exe 所在目录>/data/`
- 开发版：`<项目根>/data-dev/`
- 子目录：`images/`、`thumbs/`、`logs/`、`userData/`、`session/`
- **app ready 之前**执行：
  - `app.setPath('userData', <data>/userData)`
  - `app.setPath('sessionData', <data>/session)`
  确保 Chromium 缓存不写入 `%APPDATA%`，实现真正绿色便携。
- 启动时创建目录并做可写探测（写入临时文件再删除）；失败弹中文错误并退出，**不静默回退 AppData**。
- 使用说明注明：不要放在 Program Files、OneDrive 或只读介质中。

### 4.2 文件布局

```
data/
├── index.json          # 条目索引
├── index.json.bak      # 上一次成功写入的备份
├── settings.json       # 设置（独立文件）
├── images/<hash>.png   # 原始图片
├── thumbs/<hash>.png   # 缩略图
├── logs/app.log        # 滚动日志（无正文）
├── userData/           # Chromium userData
└── session/            # Chromium sessionData
```

### 4.3 schema v1（index.json）

```json
{
  "schemaVersion": 1,
  "items": [
    {
      "id": "uuid-v4",
      "type": "text | image",
      "createdAt": 1730000000000,
      "hash": "sha256-hex-64",
      "text": "仅 text 类型，≤200000 字符",
      "image": { "file": "<hash>.png", "thumb": "<hash>.png", "width": 1920, "height": 1080, "size": 123456 },
      "pinned": false,
      "pinnedAt": null
    }
  ]
}
```

- `createdAt`：最近一次复制时间（毫秒时间戳）。
- `hash`：文字为 UTF-8 字节 sha256；图片为所存 PNG 字节 sha256。
- `settings.json`：`{ "schemaVersion": 1, "retentionDays": 7, "launchAtLogin": false }`。

校验规则：

- JSON 无法解析 → 尝试 `.bak`；两者都失败 → 将损坏文件重命名为 `index.corrupt-<时间戳>.json`，以空索引启动并中文提示；**绝不静默清空**。
- 结构可用但个别条目非法 → 先复制一份 `index.invalid-<时间戳>.json` 留档，再跳过非法条目并记日志。
- schemaVersion 高于当前程序支持 → 不写入，提示用户升级程序（防降级破坏数据）。

### 4.4 排序、去重与搜索

- 排序：置顶区按 `pinnedAt` 倒序；普通区按 `createdAt` 倒序。
- 去重：同 `hash` 已存在 → 更新 `createdAt` 并排到最前；若为置顶条目，更新时间但**保持置顶顺序**（pinnedAt 不变）。
- 搜索：主进程对全文做 `includes`；查询去首尾空白、长度 ≤200；中文直接匹配；英文统一转小写。图片条目不参与搜索结果。分页排序同上。

### 4.5 清理、上限与孤儿文件

- 到期：`!pinned && createdAt < now - 天数×86400000` → 删除。
- 上限：总数超过 5000 → 从最旧的未置顶条目开始裁剪，直到 ≤5000。
- 时机：启动补清理；每小时一次；设置变更后立即一次；清空历史不参与自动清理。
- 删除顺序：先提交新索引，再删图片/缩略图文件（崩溃最多留下孤儿文件，不产生悬空引用）。
- 孤儿清理：启动时扫描 `images/`、`thumbs/`，删除索引中未引用的文件（限频记录数量）。
- 清空历史：删除全部未置顶条目；显示条数确认；保留置顶；随后将当前索引同时写入 `index.json` 与 `index.json.bak`（确保备份中也不残留旧历史），并删除不再引用的图片。

### 4.6 写入安全（store.js）

- 变更后标记 dirty，防抖 400–500ms 后串行写入（禁止并发写）。
- 写入步骤：
  1. 序列化到内存（紧凑 JSON）；
  2. 写 `index.json.tmp` → `fsync`；
  3. 将当前 `index.json` 复制为 `index.json.bak`；
  4. `rename(tmp → index.json)`。
- 失败重试 3 次（间隔 100–300ms），仍失败则通过 `app:error` 提示用户（中文），并保留 dirty 状态下次重试。
- 强制 flush：`before-quit`、托盘退出、Windows 关机（`powerMonitor` 的 shutdown）、窗口全部关闭不退出（仍驻留）。
- 性能门槛：3000 条时加载 <300ms、保存 <300ms、JSON <30MB；超标则按「文本正文外置」或 SQLite 迁移，store 接口保持 `list/get/upsert/pin/remove/prune/clear`。

## 5. 窗口、托盘与自启

- BrowserWindow：`frame:false`、默认 420×620、`minWidth:360`、`minHeight:500`、`maximizable:false`、`resizable:true`、`backgroundColor:#0B1E36`、`show:false`（`ready-to-show` 后显示）；按 `screen.getPrimaryDisplay().workAreaSize` 限制初始高度。
- 安全：`contextIsolation:true`、`sandbox:true`、`nodeIntegration:false`、`webSecurity:true`、preload 白名单；生产环境禁用 DevTools。
- 关闭窗口 → 隐藏到托盘（`app.isQuitting` 为真时才真正退出）。
- 托盘：`assets/tray-16.png` / `tray-32.png`；左键切换显示/隐藏；右键菜单「打开窗口」「退出」。
- 单实例：`app.requestSingleInstanceLock()`；`second-instance` 事件 → 显示并聚焦窗口。
- 开机自启：`app.setLoginItemSettings({ openAtLogin, path: process.execPath, args: ['--hidden'] })`；启动参数含 `--hidden` 时不自动显示窗口；每次启动按当前 exe 路径重新同步注册。
- 快捷键：Esc 隐藏窗口（搜索框有内容时先清空搜索）；Ctrl+F 聚焦搜索框（渲染层实现）。

## 6. 安全基线

- 渲染层无 Node 权限；所有文件与剪贴板操作在主进程。
- preload 只暴露上表方法；IPC 全部校验参数类型/范围（id 为 uuid 格式、limit ≤200、字符串长度上限）。
- 页面设置 CSP：`default-src 'self'; img-src 'self' clipimg: data:; style-src 'self'; script-src 'self'`。
- 阻断导航与新窗口：`will-navigate`、`setWindowOpenHandler` 一律拒绝。
- 生产环境阻断网络请求：`session.webRequest.onBeforeRequest` 拒绝 http/https；应用无任何联网代码、无自动更新、无 CDN。
- `webContents.setWindowOpenHandler` 返回 deny；禁止 `window.open`。
- 日志与错误信息不含剪贴板正文、不写密码类内容。

## 7. 打包方案

- `electron-builder.yml`：`appId: com.local.clipboardhistory`、`productName: 历史剪贴板`、`win.target: dir`、`asar: true`、`win.signAndEditExecutable: false`、不发布（publish: null）。
- 构建命令：`npm run dist` → `electron-builder --win --dir` → `node scripts/restore-exe.js` → `dist/win-unpacked/`。
- 整理交付：`交付/历史剪贴板-v1.0.0/` = win-unpacked 内容 + `使用说明.txt` + `SHA256.txt`；确保不包含 `data/`、`data-dev/`、源码、docs、开发日志。
- SHA256：`certutil -hashfile 历史剪贴板.exe SHA256`。
- 升级：程序文件可覆盖，`data/` 保留；schema 变更必须提供迁移函数并先备份。

### 7.1 可执行文件与系统信任（2026-11-19 实测，重要）

本机 Windows 11 的**智能应用控制（Smart App Control）处于开启状态**（注册表 `VerifiedAndReputablePolicyState = 1`）。实测：

- electron-builder 生成的 exe 会被写入图标/版本/asar 完整性资源，文件变为**未签名且哈希未知**，启动时被系统拦截（提示“已被组织策略阻止”）。
- 官方 `electron.exe` 虽同样未签名，但文件哈希已在系统信誉库中，**可以正常运行**。

因此打包流程固定为：

1. electron-builder 照常生成 win-unpacked；
2. `scripts/restore-exe.js` 用 `node_modules/electron/dist/electron.exe` 的**原始字节**覆盖 `历史剪贴板.exe`（只换文件名，不改内容）；
3. 验收要求：交付 exe 的 SHA256 必须与官方 `electron.exe` 完全一致。

代价与对策：

- exe 的嵌入图标/版本信息为 Electron 默认 → 窗口/任务栏图标由 `BrowserWindow` 的 `icon` 选项指定（使用 `assets/app-icon.png`）；阶段 6 在交付文件夹中提供带自定义图标的快捷方式（`.lnk`），资源管理器里不直接双击 exe 时可获得完整品牌体验。
- 不同机器策略可能不同，但保持官方哈希是最稳妥的通行方式。
- 交付说明中写明该背景，避免用户误以为是“未签名野程序”。

## 8. 备选方案与演进

| 场景 | 备选 |
|---|---|
| Electron 45 异步 API 阻塞 | 回退 Electron 44 最新补丁版（仍为异步 API）；极端情况评估 43（旧同步 API，需重写采集层） |
