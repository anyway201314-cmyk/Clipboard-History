# 04 · 开发规范与执行步骤

> 文档状态：生效（阶段 0 创建）
> 最后更新：2026-11-19
> 说明：本文规定「怎么做」。需求以《01-需求与范围》为准，技术细节以《02-技术方案》为准，界面以《03-界面设计规范》为准。

## 1. 总原则

1. **一次只推进一个阶段**：未完成当前阶段验收，不开始下一阶段。
2. **先验证，后依赖**：风险技术点（Electron 45 异步剪贴板、便携路径、打包）必须在阶段 1 用最小骨架验证通过。
3. **数据安全优先于功能速度**：任何可能导致用户数据丢失的实现都必须先补测试与保护措施。
4. **可回滚**：每个阶段结束提交本地 git，并在用户确认后打 `stage-X` tag。
5. **不过度工程化**：单人小工具，不引入框架、测试框架、构建器；能用 50 行写清楚的不引入 500 行抽象。
6. **用户确认是门禁**：到达确认点必须停下汇报，未确认不得进入下一阶段。

## 3. 每阶段标准工作流

1. **开始**：阅读 `CLAUDE.md` → `开发日志/待办总览.md` → 最新日志 → 相关 docs；向用户复述当前阶段与今日目标。
2. **实施**：小步实现当前阶段任务；长构建、打包、批量改动前先写一行进度到当日日志（防会话中断）。
3. **自测**：运行 `node --test` 与《05-测试与验收清单》对应阶段用例；记录结果。
4. **文档**：需求/技术/设计有变化，先更新对应 docs 并记录变更，再改代码。
5. **日志**：更新当日 `开发日志/YYYY-MM-DD.md` 与 `待办总览.md`；阶段完成时写验收记录。
6. **汇报与提交**：git 提交；向用户汇报（非程序员可懂的语言）；到达确认点时暂停，等待确认；确认后打 `stage-X` tag。

## 4. 阶段门禁与验收记录

- 阶段完成必须满足：
  1. 本阶段验收标准全部达成；
  2. 相关测试用例记录在《05-测试与验收清单》；
  3. 当日开发日志与待办总览已更新；
  4. git 已提交；
  5. 用户在确认点明确确认。
- 未满足以上条件，不得标记阶段完成、不得打 tag、不得开始下一阶段。
- 验收记录格式（写在《05》末尾或当日日志）：`阶段 | 日期 | 验收项 | 结果 | 用户确认日期 | git tag`。

## 5. 目录与命名约定

```
历史剪贴板/
├── CLAUDE.md
├── docs/                  # 标准文档（01–06）
├── 开发日志/               # README + 待办总览 + YYYY-MM-DD.md
├── .claude/commands/收尾.md
├── src/main/*.js          # 主进程模块（kebab-case）
├── src/preload.js
├── src/renderer/          # index.html + css/ + js/
├── assets/                # 托盘图标
├── build/                 # 应用图标（icon.ico / icon.png）
├── tests/                 # node:test 用例
├── scripts/               # 开发辅助脚本（seed 等）
├── data-dev/              # 开发数据（git 忽略）
├── data/                  # 运行数据（git 忽略）
├── dist/                  # 构建原始输出（git 忽略）
└── 交付/                   # 整理后的交付物（git 忽略）
```

- 文件名：主进程模块 `kebab-case.js`；渲染层脚本 `app.js / render.js / time.js`。
- 数据字段：`camelCase`；CSS 变量：`--kebab-case`。
- IPC 通道：`域:动作`（如 `items:query`）。
- 常量集中放置，禁止魔法数字散落（轮询间隔、上限、保留天数范围等）。
- 数据路径只能通过 `src/main/paths.js` 获取；任何模块不得自行拼接数据目录。

## 6. 编码规范

- 主进程 CommonJS（`require`）；渲染层普通 `<script>`（无 ES Module、无打包器）。
- 2 空格缩进；分号；单引号；`const`/`let`，禁用 `var`。
- 异步统一 `async/await` + `try/catch`；IO 调用不得裸奔。
- 函数保持单一职责；纯逻辑（时间格式化、搜索匹配、清理判定）独立为纯函数，便于 `node:test`。
- 标识符用英文；复杂逻辑写中文注释说明「为什么」，不复述代码。
- 不引入任何新依赖（含前端库、工具库）需先询问用户；Electron 版本不自行升级。
- 不引入 TypeScript、打包器、CSS 框架；不写 inline script（CSP 限制）。
- 代码中不出现 `http://`、`https://` 外链资源；不加载 CDN。

## 7. 安全与 IPC 规范

- 渲染层：`contextIsolation:true`、`sandbox:true`、`nodeIntegration:false`、`webSecurity:true`；生产环境关闭 DevTools。
- preload 只暴露《02》IPC 白名单方法；不得暴露 `ipcRenderer`、`require`、`process` 等原始对象。
- IPC 参数全部校验：id 为 uuid 格式；limit 为 1–200 整数；搜索字符串 ≤200 字符；设置值在允许范围。
- CSP 按《02》配置；`will-navigate` 与 `setWindowOpenHandler` 一律拒绝外部导航/新窗口。
- 生产环境阻断所有 http/https 网络请求（`webRequest.onBeforeRequest`）。
- 日志与错误提示不得包含剪贴板正文、文件路径中的用户名等敏感信息。

## 8. 错误处理与日志规范

- 用户可见错误：中文、说明「发生了什么 + 怎么办」（如「数据保存失败，请检查磁盘空间或文件夹权限」）。
- 技术细节写 `data/logs/app.log`：时间、模块、错误码/消息；限频（同类错误每分钟最多 3 条）；不写正文。
- 任何写盘/读盘失败不得静默忽略；至少记录日志并提供 UI 提示路径（`app:error`）。
- 启动阶段的关键失败（数据目录不可写、双索引损坏）：显示中文错误对话框后退出或以隔离模式启动，绝不静默清空数据。
- 剪贴板读取失败（被占用等）：下一轮重试，不中断循环，不弹窗打扰用户。
- 图片文件缺失：该卡片显示「图片已丢失」占位，不崩溃；日志记录一次。

## 9. 数据安全红线（不可违反）

1. 禁止直接编辑/删除真实 `data/`；开发测试只用 `data-dev/`；确需清理真实数据必须用户在场确认。
2. 禁止无迁移的数据结构变更；改 schema 前备份并在日志记录。
3. 置顶内容永不自动删除；删除置顶、清空历史必须二次确认。
4. 索引写入必须原子（tmp + fsync + rename）并维护 `.bak`；禁止直接在原文件上覆盖写。
5. 主文件与备份都损坏时，必须隔离损坏文件并提示用户，禁止静默重建空索引。
6. 清空历史必须同步清理 `.bak` 中的旧内容与不再引用的图片。
7. 日志不得记录剪贴板正文。
8. 测试数据脚本只允许写入 `data-dev/`，且运行前确认路径。

## 10. git 规范

- 本地仓库，无远程；禁止 `git push`（除非用户明确要求添加远程）。
- 每个完成的工作单元提交一次；提交信息格式：
  - 标题：`阶段N: 摘要`（中文，≤50 字）
  - 正文：要点列表（可选）
  - 末尾署名：`Co-Authored-By: Claude Code <noreply@anthropic.com>`
- 阶段完成后打 tag：`stage-0` … `stage-7`，最终版本打 `v1.0.0`。
- 禁止提交 `data/`、`data-dev/`、`dist/`、`交付/`、`node_modules/`。
- 提交前运行 `git status` 检查，确保没有数据文件或敏感内容进入版本库。

## 11. 开发日志与待办规范

- 当日日志：`开发日志/YYYY-MM-DD.md`，字段：今日目标 / 完成事项 / 决策与理由 / 问题与解决 / 风险与注意 / 待办 / 下次从这里开始。
- 待办总览：`开发日志/待办总览.md`，顶部记录当前阶段、状态、下一检查点、上次更新时间；表格 `ID | 事项 | 阶段 | 状态 | 备注`；未完成事项只滚动、不删除。
- 每次会话结束前必须执行 `/收尾`（或在 CLAUDE.md 指引下手动完成同等步骤）：更新日志、待办、测试、提交，并给出三行摘要与下次起点。
- 当天无开发则无需新建日志。

## 12. 构建、测试与发布步骤

开发命令（阶段 1 建立后生效）：

| 命令 | 用途 |
|---|---|
| `npm start` | 开发运行（Electron） |
| `npm run selftest` | 自动化采集自检（临时改写剪贴板，结束恢复） |
| `npm run cpu-test` | 自检 + 4K 图 5 分钟 CPU 实测 |
| `node --test` | 运行纯逻辑测试 |
| `npm run dist` | electron-builder 打包（`--dir`）并自动用官方 exe 覆盖产物 |
| `npm run seed` | 生成 `data-dev/` 种子数据（仅开发） |

**开发环境注意**：当前终端存在 `ELECTRON_RUN_AS_NODE=1`（VSCode 环境变量），运行 Electron 时必须先清除（`env -u ELECTRON_RUN_AS_NODE npm ...`），否则 Electron 会以纯 Node 运行、`require('electron')` 返回路径字符串。

发布步骤（阶段 6）：

1. 确认工作区干净、所有测试通过、版本号 1.0.0。
2. `npm run dist` 生成 `dist/win-unpacked/`。
3. 整理 `交付/历史剪贴板-v1.0.0/`：程序文件 + `使用说明.txt` + `SHA256.txt`；确认无 data、源码、docs、日志。
4. `certutil -hashfile 历史剪贴板.exe SHA256` 记录哈希。
5. Defender 扫描；全新数据目录冒烟测试；移动文件夹测试。
6. 更新《06-打包发布与使用说明》与开发日志；提交；用户验收后打 `v1.0.0` tag。

## 13. 会话中断与恢复

- 长任务（安装依赖、打包、批量测试）开始前，先写一行进度到当日日志。
- 会话中断后，下次从最新日志「下次从这里开始」继续，不凭记忆重做。
- 若发现日志与实际进度不一致，以代码与测试结果为准，并立即修正日志。
