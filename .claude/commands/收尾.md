执行项目会话收尾流程（依据项目 `CLAUDE.md` 与 `docs/04-开发规范与执行步骤.md`）：

1. **更新当日日志** `开发日志/YYYY-MM-DD.md`（按今天日期；不存在则用 `开发日志/README.md` 的模板新建）：
   - 今日目标 / 完成事项 / 决策与理由 / 问题与解决 / 风险与注意 / 待办 / 下次从这里开始
   - 根据本会话的实际工作如实填写，不编造。
2. **同步待办总览** `开发日志/待办总览.md`：更新当前阶段、状态、下一检查点、上次更新时间与表格状态；未完成事项只滚动不删除。
3. **测试**：如果已有代码，运行 `node --test` 并报告结果；失败项写入日志与待办。
4. **检查阶段门禁**：若当前阶段验收标准已满足，提醒用户这是确认点，等待用户确认；未确认前不得标记完成或进入下一阶段。
5. **git**：`git status` 检查无 `data/`、`data-dev/`、`dist/`、`交付/`、`node_modules/` 进入版本库；如有变更则提交（标题 `阶段N: 摘要`，末尾署名 `Co-Authored-By: Claude Code <noreply@anthropic.com>`）。用户确认阶段完成后才打 `stage-X` tag。
6. **输出三行摘要**：
   - 今天完成了什么（面向非程序员，通俗中文）
   - 风险 / 阻塞 / 需要用户决定的事
   - 下次从哪里开始（具体到文件和任务）

注意：日志中不得包含剪贴板正文、密码等敏感内容。若今天没有实际开发，也要说明会话状态（如「等待用户确认」）。
