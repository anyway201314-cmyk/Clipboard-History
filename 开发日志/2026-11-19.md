## 决策与理由

- **技术栈锁定 Electron 45.4.1 + 原生 HTML/CSS/JS**：本机只有 Node 工具链；零运行时依赖最稳；无框架降低复杂度。不中途升级 Electron。
- **剪贴板采集用异步轮询（主进程）**：Electron 45 无剪贴板事件；文本 600ms、图片 1.5s；避开原生模块与 PowerShell 常驻进程。
- **存储用 JSON + 原子写 + `.bak`，不用 SQLite**：数据规模小（≤5000 条、7 天），无编译环境，JSON 可读可备份；性能门槛与迁移预案写入技术方案。
- **数据目录 `data/`（打包）/ `data-dev/`（开发）**：迁移 userData/sessionData，保证 AppData 无残留、整目录可携带。
- **点击卡片复制不改变排序与时间**：避免「使用历史」造成列表跳动；通过自写抑制实现。
- **启动时已有剪贴板只作基线**：避免把启动前的敏感内容写入历史。
- **搜索时隐藏图片、置顶区参与过滤**：图片无法按内容检索，避免干扰。
- **缩略图统一 PNG**：不依赖 webp 编码器，降低风险。
- **每阶段用户确认 + git tag**：稳定、安全、可回滚；用户强调不要一次做完。

## 风险与注意

- Electron 45 异步剪贴板 API 对不同来源（Chrome/Word/微信/截图工具）返回的 MIME 需阶段 1 实测，图片提取策略可能微调。
- 轮询存在漏记窗口（文本 <600ms、图片 <1500ms），已写入需求已知限制与使用说明。
- 4K 图片持续在剪贴板的 CPU 占用需阶段 1/5 实测，超标则降频。
- 中文 exe 文件名、打包后数据路径、Defender 误报需阶段 1/6 验证。
- 阶段 1–5 只用 `data-dev/`，防止污染真实数据。
