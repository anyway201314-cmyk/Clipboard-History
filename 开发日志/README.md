# 开发日志说明

本目录记录「历史剪贴板」项目的每日开发进度、决策与待办。它是项目推进的「工作记忆」，也是会话中断后恢复工作的第一入口。

## 文件约定

| 文件 | 用途 |
|---|---|
| `README.md` | 本说明 |
| `待办总览.md` | 滚动待办总表；每次会话开始与结束都要查看/更新 |
| `YYYY-MM-DD.md` | 当日的开发日志；按自然日新建 |

## 每日日志模板

```markdown
# YYYY-MM-DD 开发日志

## 今日目标
- …

## 完成事项
- …

## 决策与理由
- …

## 问题与解决
- …

## 风险与注意
- …

## 待办（同步到 待办总览.md）
- [ ] …

## 下次从这里开始
- …
```

## 规则

1. **每次开发会话开始**：先读 `待办总览.md` 与最新一篇日志，再开始工作。
2. **每次开发会话结束**：必须更新当日日志与 `待办总览.md`（或执行 `/收尾` 命令）。
3. 跨天继续工作时，新建当日日志，并把未完成待办滚动复制过去。
4. 未完成事项只能滚动传递，不能直接删除；放弃的事项标记「取消」并写明原因。
5. 阶段完成时记录验收结果与用户确认日期（写入《docs/05-测试与验收清单》K 区）。
6. **日志中不得写入剪贴板正文、密码等敏感内容**；只记录事件类型、数量、耗时、哈希前几位等。
7. 当天没有开发则无需新建日志。
8. 长任务（安装依赖、打包、批量测试）开始前，先写一行进度，防止会话中断导致信息丢失。
